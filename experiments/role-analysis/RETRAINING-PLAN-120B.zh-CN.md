## 1 训练目标与数据边界

分类器固定输出六类，顺序为 `system, developer, user, cot, assistant, tool`。本轮的“重新训练”指小分类器及其特征选择、标准化从本轮合成训练集重新开始；120B 本体冻结，不做全参数微调或 LoRA。

| 符号 | 含义 | 是否作为分类目标 |
| --- | --- | --- |
| S | 原生 `system` 消息正文 | 是 |
| D | 原生 `developer` 消息正文 | 是 |
| U | `user` 消息正文 | 是 |
| C | `assistant` 的 `analysis` 正文 | 是 |
| A | 普通 assistant 正文；本轮五种基本模板中为最终回答 | 是 |
| Q | assistant 发出的工具调用，含工具名、参数和调用结束标记 | 否，保留为结构上下文 |
| T | 与 Q 对应的工具回复正文 | 是 |

S 和 D 必须用各自的原生消息头，不能通过会把 system 改映射为 developer 的默认模板混用。C 是一个操作性分类标签，表示正文所在的 analysis channel；文章片段放在这里不等于它具有真实推理语义。

本轮训练、验证、选头、标准化、早停和模型选择均不使用真实对话，也不使用大模型编造的对话。现有最优分类器及使用过自然对话的特征排序不作为初始化。这个约束针对本轮 probe 数据，不能据此声称预训练的 120B 本体从未接触过对话。

真实对话只在模型和所有参数冻结之后用于最终测试，不用其结果重新选择模型。此前的训练过程和结果保留在 [原训练指南](TRAINING-GUIDE-120B.zh-CN.md)，不作为本轮已经取得的效果。

## 2 单消息和单轮结构

“单消息”指只有一条独立消息；“单轮”指只有一条用户请求，但它可以跨多次模型调用和一次工具交互；“多轮”指包含多条用户请求。工具返回后再次调用模型，不自动算作新的一轮用户请求。

### 2.1 独立单消息

分别构造独立的 S、D、U、C、A、T 消息，正文来自非对话文章。它们用于学习和诊断各角色的特征。独立 T 等样本不是完整 agent 交互，不与完整对话的结构合法性混为一谈。

### 2.2 单个用户轮次

**原始单轮模板严格固定为用户确认的以下五种：**

| 模板 | 覆盖的情况 |
| --- | --- |
| `SDUA` | 用户输入后直接回答 |
| `SDUCA` | 用户输入后先输出 CoT，再回答 |
| `SDUCQ` | 用户输入后输出 CoT 和工具调用，样本停在等待工具结果的位置 |
| `SDUQTCA` | 工具调用和回复之后，产生新的 CoT，再回答 |
| `SDUQTA` | 工具调用和回复之后直接回答，没有可见 CoT |

每条都只有一个开头的 SD。Q 的工具和参数必须符合相应工具定义，T 必须匹配 Q；工具不实际执行。工具定义和 Q 的 JSON 由确定性规则构造，T 的监督正文仍取文章片段。

`SDUCQ` 是有意保留的未完成工具阶段，不在同一条原始模板后偷偷补入 T 或 A。`SDUQTCA`、`SDUQTA` 的可见结构中没有 Q 之前的 C：它既可表示没有输出这段 C，也可表示该 C 已被 agent 清理，二者用调用阶段的来源记录区分。

## 3 多轮的有放回抽样规则

去掉上述五种模板开头的 SD，片段集合为：

```text
UA, UCA, UCQ, UQTCA, UQTA
```

先确定用户轮数 K。**开头只放一次 SD，每个片段允许重复抽取，UCQ 只能出现在最后。** 实现规则为：

1. 前 K−1 个片段，从 `UA, UCA, UQTCA, UQTA` 中独立、均匀、有放回抽取。
2. 最后一个片段，从全部五种中均匀抽取。
3. 按顺序拼接，并在最前面加一次 SD。

```text
SD + UA + UCA + UQTA
SD + UQTCA + UQTCA + UCQ
SD + UQTA + UA + UQTCA
```

固定 K 时有 `5 × 4^(K−1)` 个合法组合，最后为 UCQ 的概率是 20%。训练时 K 在 2、3、4 中均匀抽取；单轮 K=1 单独分配配额。最终合成测试额外覆盖 K=5、6 的长组合。以上“均匀”指原始结构抽样；正文 token 长短不同，不能据此声称各结构获得相同数量的监督 token。

当前规则中，每个用户轮次最多一组 Q/T；多个用户轮次可以分别调用工具。原先设想的其他前缀和同一用户轮次多次工具循环，不混入本次正式原始模板。

## 4 每次模型调用与 CoT 清理

### 4.1 同一用户轮次内省略先前 CoT

覆盖用户指定的实际调用过程：

```text
某次模型输出后的记录： SDU C_before Q
工具返回后的实际输入： SDU          Q T
接着得到的新输出：     SDU          Q T C_after A
```

第一阶段对应 `SDUCQ`，后续可见结构对应 `SDUQTCA`。如果最终不再产生 C，则对应 `SDUQTA`。前后阶段通过同一个调用链 ID、Q/T 和正文来源记录关联，但不把 UCQ 作为一个已经完成的中间用户轮次拼接进多轮。

原始五种模板与调用快照分别记录：`template_id`、`round_segments`、`snapshot_stage`、`history_policy`、`call_chain_id`。逻辑事件记录可以保存已经被删除的 C；实际模型输入只包含该次调用真正可见的消息。

### 4.2 多用户轮次之间的 CoT 清理

对确实存在历史 C 的轨迹，构造保留历史 C、删除已完成用户轮次 C，以及删除先前调用 C 的适用版本。不存在的 C 不凭空补入。删除后，部分可见结构可能与另一种模板相同，来源仍按原轨迹记录。

OpenAI 官方的处理建议是：当前工具链未结束时保留相应 CoT，最终回答完成后在后续调用清理；本轮额外覆盖工具返回时就省略先前 C 的部署方式。[官方 CoT 处理说明](https://developers.openai.com/cookbook/articles/gpt-oss/handle-raw-cot)

原始训练模板仍只有上述五种。若额外比较 `SDUCQTCA` 这种保留工具前 C 的完整版本，将它列为独立的部署诊断样本，不作为第六种原始训练模板，也不把它的分数混入五种模板的正式指标。

### 4.3 特征与统计的处理

- 删除整条 C 消息，包括头部和边界，然后重新分词、定位正文、执行模型 forward。删除后的后续特征不能沿用删除前的 hidden states 或旧 KV cache。
- 原始版本、清理版本及其源文章属于同一数据划分，不能跨训练、验证、测试集。
- 使用稳定的消息、事件和正文位置 ID，避免 S/D/U 等历史正文因为快照多而被重复大量计权。只为新增目标正文和明确分配的上下文对照保留训练行，对同一对照家族归一化计权。
- `SDUCQ` 和 `SDUQT` 是前后阶段，目标正文不同，不能直接拿两者的整体准确率声称删除 C 的因果效果。做配对诊断时，固定同一份 T 或后续新 C/A，再比较不同上下文。
- 某样本没有 C 或 T 时，对应类别的召回率记为 N/A，另外报告误报，不能把没有该类别算成识别成功。

## 5 文章来源与数据配额

C4 与 Dolma3 按源文章数量各占约一半，默认使用英文。先过滤，再按源文章及近重复簇划分，最后生成消息包装和调用快照。

过滤聊天记录、问答、访谈、剧本、连续说话人标签及疑似真实对话；不确定的文章舍弃，保存过滤日志并抽样审计。不能只凭数据集名称就保证没有对话。文章正文不得含保留的 Harmony 控制串，但不因普通单词 system、user 等就整篇删除。

| 阶段 | FIT 源文章 | DEV 源文章 | 合成 TEST 源文章 |
| --- | --- | --- | --- |
| 小规模试验 | 512 | 128 | 不打开正式 TEST |
| 正式实验 | 4096 | 512 | 1024 |

小试数据是正式对应划分的子集。规范化正文、URL 及近重复簇不能跨划分。结构版本、CoT 清理版本、文章派生片段随源文章一起归属相同划分。

监督正文 token 的目标比例为：独立单消息 20%、单用户轮次 30%、多用户轮次 50%。单轮五种原始模板按样本配额平衡；多轮按第三节规则抽取。在适用的轨迹中平衡保留和清理历史 C 的版本，不通过插入额外 C 改写五种原始模板。

小试最多保存 25 万条正文特征，正式 FIT 最多保存 200 万条正文特征；DEV/TEST 单独计数。上限是缓存和时间控制，不是需要重复凑满的样本数。按固定种子、结构和存在的角色采样，冻结并报告最终每源、每结构、每角色的实际数量。

正文使用不同长度、不同位置的文章片段，不统一固定为 48 token，不在每个轮次机械重复同一小段。全文输入上限为 4096 token，包含 SD、工具定义、历史、Q、边界及当前输出。超出时重新分配正文长度或重新采样，不在消息中间截断；测试 K=5、6 也遵守此上限。

## 6 原生格式与监督位置

渲染器显式生成原生 Harmony 格式。Q 使用匹配工具 recipient 的 assistant 工具调用头，结束于 `<|call|>`；C 使用 `analysis`，A 使用 `final`。最终输出的停止标记和持久历史的结束标记按各自用途处理。[Harmony 格式说明](https://developers.openai.com/cookbook/articles/openai-harmony)

保留两个独立的标注层：

1. **形式角色与事件标注**：解释每条消息、头部、正文、Q/T 对应关系。
2. **正文监督 mask**：只包含来自文章片段的正文 token，作为六类训练与正式评分的位置。

整个消息头，包括普通文字 `system`、`developer` 和 channel 名，以及 delimiter、结束标记、Q 的 JSON、工具定义均不作为分类目标。它们完整保留在模型输入中。D 消息中的工具定义属于 D 的结构上下文，不能当作文章监督正文。

解析器须独立复核 token/字符区间，先识别带 recipient 的 Q，再识别普通 assistant 正文，显式支持 D。可视化展示完整上下文并标出未评分结构；正式 accuracy 的分母只使用正文监督 mask。

## 7 分类器训练与选择

先在小试 FIT 内部划出选头统计和内部评估子集，对所有 attention heads 做六类区分能力扫描，选择 16 个头。DEV、TEST、真实对话及旧自然对话选头结果均不参与本轮选头。随后固定头顺序，正式提取这 16 个头的 `pre-o_proj` 特征，每个目标 token 为 1024 维。

全头扫描在线累计统计，不保存所有头的完整特征库。选定后的特征保存为 FP16，按分片和 memmap 读取。仅标准化器和小分类器参与后续训练，标准化参数只由 FIT 估计。

| 候选 | 结构 | 随机种子 |
| --- | --- | --- |
| 线性基线 | 1024 → 6 | 17 |
| 小 MLP | 1024 → 128 → 6 | 17、29、43 |
| 较大 MLP | 1024 → 256 → 6 | 17、29、43 |

七个候选共用同一份特征库，依次在 GPU 上训练，无需反复加载 120B 或再提取特征。默认用 PyTorch 标准交叉熵与 AdamW，学习率 `1e-3`、weight decay `1e-3`、MLP dropout `0.1`、分类器 batch size 4096、梯度裁剪 5。最多 45 epochs，至少训练 10 epochs，早停 patience 为 8；小试最多 15 epochs，用于工程和耗时验证。不存在的结构—角色组合不能靠补造样本强行平衡；采用适用角色与结构的平衡采样，不再叠加类别权重。

DEV 选择顺序固定：优先满足六类汇总 precision、recall 均达到 90% 的候选，再按结构等权 macro-F1、最弱类别的 min(precision, recall)、NLL、固定候选 ID 依次比较。无候选达标时仍交付最佳候选并说明差距，不使用 TEST 反向挑选。

已实现参数化运行入口 `run_synthetic_agent_roles.py`，提供 `prepare / preflight / scan / extract / train / freeze / evaluate / report` 等阶段，以及 `--config --model-dir --data-dir --run-dir --cache-dir --devices --resume`。后台阶段调度、审计门禁与 24 小时硬截止由 `run_synthetic_agent_campaign.py` 执行。

导出新的六类 `best.npz` 与消费端加载代码，元数据固定模型/tokenizer 版本、六类顺序、选头顺序、标准化器、特征位置和格式版本；不能让旧五类加载器默默把 D 当作 S。

## 8 A40 数量与显存依据

**推荐同一台服务器的 4 张 A40，每卡标称 48 GB。四张覆盖大模型特征提取、GPU 分类器训练和最终测试，不需要额外再加一张训练卡。** 分类器训练阶段释放 120B 后，使用其中一张即可，其余候选顺序运行。

这里的 GPU 训练指大模型权重与 forward、小分类器梯度更新在 GPU；CPU 仍负责文本处理、分词、文件读写及绘图。120B 不参与反向传播，因此不能把本计划的资源需求用于全参数微调。

| A40 数量 | 本轮资源判断 |
| --- | --- |
| 1 张 | 不能完整驻留约 60.77 GiB 的原始权重，不符合本方案的大模型全 GPU 驻留要求 |
| 2 张 | 静态容量看可能，但未验证新加载布局、运行 workspace 和 4096 token；不作为正式资源承诺 |
| 3 张 | 也是尚未验证的新布局，当前没有证据把它定为所需最低配置 |
| 4 张 | 已有同项目冻结 120B 原生 MXFP4 运行实证，本轮采用的配置；新长度需通过预检 |

A40 的标称显存来自 [NVIDIA 规格](https://www.nvidia.com/en-in/data-center/a40/)。已有实验记录中，官方 15 个权重分片总大小为 65,248,893,184 bytes，约 60.77 GiB；模型 36 层按每卡 9 层分布在四张 GPU 上。四卡全设备监控峰值约为 32.24、29.69、31.42、32.52 GiB。此组峰值对应此前约 1035 token 上限的初始提取，不能当作新 4096 token 输入的实测显存。

证据见 [历史模型后端](outputs/local-gptoss120b/model_backend.json)、[历史显存监控](outputs/local-gptoss120b/gpu-memory-summary.json)、[历史输入清单](outputs/local-gptoss120b/manifest.json)及[权重校验](outputs/local-gptoss120b/gardening-final-checkpoint/weight-verification.json)。全卡监控包含设备上的其他 CUDA 上下文，不能当作纯模型分配量。权重文件大小也不是加载后峰值显存；仍要计入计算 workspace、激活和 CUDA 分配。

新服务器先用大模型 forward batch size 1，检查短输入及最长 4096 token 的峰值、模型输出和 hook 无扰动，再决定是否提高 batch。小分类器的 batch size 与大模型 forward batch size 分开配置。全头扫描也按相同上限做预检，不同时缓存各层所有激活。

A40 是 Ampere，不能直接照搬官方针对较新架构的 MXFP4 安装示例。复用项目已经验证的 A40 兼容后端和版本固定方式，确认专家权重保持 MXFP4，拒绝静默反量化为全模型 BF16。原生 MXFP4 是权重格式和对应专家实现，不代表 A40 具有较新 GPU 的原生 FP4 Tensor Core。[官方 Transformers 部署说明](https://developers.openai.com/cookbook/articles/gpt-oss/run-transformers)

四卡先采用已有的按层分片方案；旧实现的同步 CPU staging 只搬运跨卡激活，不是将权重卸载到 CPU。预检记录新服务器的实际传输方式。四张卡不等于把权重全部压进一张连续显存，仍需正确的设备布局。

| 最终测试与报告 | 远端 GPU 与 CPU | 合成测试、冻结后真实测试、tomato 图片、报告 |
| 结果同步 | SSH 与 rsync | 分类器、配置、图表和报告回传仓库，再提交并 push |

使用服务器现有调度器，或在没有调度器的独占任务环境中用 tmux 后台运行。SSH 断开后任务继续；机器重启或任务退出后的恢复依靠 checkpoint，tmux 本身不提供训练恢复。

特征提取按分片原子写入，记录输入、输出、模型、配置哈希；恢复时跳过已校验完成的分片。训练 `last.pt` 保存模型、optimizer、step/epoch、RNG、采样器状态与早停状态。配置、模型、头顺序或数据不同的缓存不能混用。

模型、特征和 checkpoint 保存到持久 SSD；`/dev/shm` 仅可作临时加速，不能是唯一副本。16 头的 FP16 特征每百万位置约 1.91 GiB，尚未包含标签、索引、DEV/TEST、快照及运行环境。服务器建议至少 128 GiB RAM、300 GiB 可用持久 SSD，最终以小试实际用量为准。

不需要普通聊天 API：当前工作需要在服务器进程内安装 hook、提取内部特征并训练分类器。若只能开放 API，需要另做支持提交任务、查询状态、读取日志、下载产物、停止与恢复任务的作业管理接口；SSH 是本计划默认方案。

耗时不在硬件和小试未知时预估成固定天数。小试分别测选头、每千输入 token 的提取耗时、候选训练与评估耗时，再按正式实际快照 token 数估算 GPU 小时，计入重算 CoT 清理版本和结果验证。本轮用户已授权最多连续 24 小时；正式调度依据实测小试、完整正式输入 token 清单和保守余量执行预算门槛，不通过缩减配额放行。

## 10 测试与交付

合成 TEST 以从未参与训练、验证的新文章构造：一部分使用单轮五种和 K=2–4 的多轮规则，一部分使用 K=5、6 的长组合。按源文章划分防止正文泄漏；长组合测试是组合长度泛化，不声称引入了第六种单轮模板。

报告六类 precision、recall、F1、混淆矩阵、总体 accuracy、macro-F1，以及单消息、各单轮模板、轮数、工具阶段、CoT 清理策略和位置/长尾的分项效果。正式评分只取文章正文 mask。按源文章簇做 2000 次 bootstrap，单列置信区间。

预定正式合成测试目标为：汇总 macro-F1 至少 95%，六类汇总 precision、recall 各至少 90%。这是目标点估计，不是已实现结果，也不是置信区间下界承诺。若未达标，交付实际最优候选、分项失败分析和完整复现信息。

模型冻结后，再用与历史拟合数据去重的 128 条 OASST、128 条 ToxicChat 做真实对话外部测试。需要补的 S/D 前缀在开测试前固定，并说明它们不是原对话生成时的原始上下文；没有 C/T 的测试不报告其召回率。原论文 gardening 对话保留为历史诊断，不能当作从未看过的盲测。

交付内容包括：

- 新的六类 `best.npz`、加载与预测代码，及包含六类顺序和模型绑定信息的冻结清单。
- 数据过滤、源文章划分、五种模板、多轮抽样、快照、正文 mask 和实际采样计数清单。
- 参数化运行入口、固定依赖与模型版本、GPU 预检、日志、训练曲线、恢复示例和完整结果报告。
- 覆盖五种单轮、多轮重复抽样、末尾 UCQ、CoT 清理的 tomato PNG/PDF，以及只含新分类器的单列图。图中显示完整 SD 与结构上下文，未评分位置明确标出。
- 正常 delimiter 的主结果；统一 user 和去标签版本作为额外诊断，不把原角色语义分数称为改变格式后的形式角色 accuracy。
- 小型产物回传、哈希校验、Git 提交和 push；大模型与大型特征缓存留在远端。

完成标准是：数据规则与 mask 校验通过，4×A40 的最长输入预检通过，GPU 分类器训练及恢复验证通过，按固定 DEV 规则冻结模型，完成 TEST 与图表并回传。准确率是否达标单独报告，不用修改测试集或测试后挑模型补足。
